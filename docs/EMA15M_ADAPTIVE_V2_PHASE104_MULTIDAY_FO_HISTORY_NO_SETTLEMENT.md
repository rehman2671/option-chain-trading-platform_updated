## Why current-day account review was insufficient

Phase103 inspects a full current ordinary broker order book, GTT list and position rows, but **ordinary Upstox order book is day-limited**. Multi-week options may have an original BUY several trading days earlier. Missing from today's book is not an unfilled, cancelled or nonexistent order. Phases99–102 retain private original BUY and SELL child receipts and individual broker-reported trade IDs; the current account snapshot and older trade ledger need a separate, date-ranged corroboration source.

Upstox [Get Trade History](https://upstox.com/developer/api-documentation/get-historical-trades/) is `GET /v2/charges/historical-trades`, accepts `segment=FO`, `start_date`, `end_date`, `page_number` and `page_size`; has a documented last-three-financial-year limit and up to 5000 items per page. Its F&O example identifies each record by `trade_id`, `trade_date`, `exchange` (NFO), `option_type` (CE/PE), `scrip_name`/symbol, `strike_price`, `expiry`, `transaction_type`, `quantity` and `price`. **Critically, it does not provide a reliable F&O original `order_id` or populated option `instrument_token`.** Therefore matching this API to separate current-day order/trades is broker-reported **cross-source corroboration**, never a signed independent exchange receipt or guaranteed order-to-trade linkage. Do not fabricate missing IDs.

## Implemented

1. `UpstoxProvider.getHistoricalFoTradesPage(startDate,endDate,pageNumber,pageSize)`: GET-only with authenticated bearer token, strictly bounded FO query, dates `YYYY-MM-DD`, page index 1–20 and fixed `page_size=1000`. Any disconnection, response error or malformed payload returns `null`, not an empty array masquerading as absence. No credentials or raw account rows are returned by the public API.
2. Pure `adaptiveHistoricalFoTradeReview.ts`: validates account scope; NSE NFO or BSE BFO; underlying name, CE/PE, original strike, expiry; start date equal to original **India trading date** and end date equal to a known **as-of India date**, non-future and bounded to 120 days. The date range accommodates 1W–8W positional research while preventing broad unconstrained private account extraction.
3. The collector authenticates the exact connected account **before** any page fetch; sequentially requests pages 1…N and strictly checks consistent metadata `meta_data.page.total_pages`, `total_records`, page sequence, last-page completeness, 20-page limit and 20,000-row bound. Missing pages, count drift, broker errors or malformed rows fail closed; page one cannot be used as a complete response if metadata expects more.
4. The auditor requires unique immutable Phase101 BUY and Phase99 SELL trade IDs with strictly positive quantity and paise-compatible price, sums equalling the original long and already-observed SELL child fills, and disjoint BUY/SELL IDs. Every expected `trade_id` must appear exactly once in the fully paginated FO history, with identical direction, quantity and execution price, and matching exchange, underlying, option type, strike and expiry. Missing one ID returns `HISTORICAL_FO_SOURCE_INCOMPLETE`, conflicting ID/contract/price or extra same-contract BUY/SELL execution returns `HISTORICAL_FO_TRADE_CONFLICT`. Unrelated FO contracts are not silently deemed a complete capital ledger.
5. SUPERADMIN-only `POST /api/ema15m/historical-fo-trade-review` accepts only `{positionId,expectedAccountId}`. It reads the exact `EXIT_PENDING` option and private immutable joint receipts; derives entry date from persisted timestamp using the **Asia/Kolkata trading timezone** and end date from the current Indian calendar day, never arbitrary user-supplied account-wide extraction dates. It fetches historical FO pages using the authenticated broker account, then **fresh** unique broker net; finally re-reads the SQLite joint ledger to block local source races. Requires the original BUY/SELL ledger + current broker net to still match Phase102's conservative joint preview. Outputs only sanitized reason codes, page/trade counts and joint state—no account ID, option native key, order/trade IDs, broker credentials, individual prices or indicative P&L.
6. Every state (including `BROKER_REPORTED_MULTIDAY_TRADES_MATCH_NOT_CERTIFIED`) explicitly returns `brokerHistoricalOrderIdPresent:false`, `brokerHistoricalInstrumentTokenPresent:false`, `historicalTradesIndependentlyCertified:false`, `signedContractNotesReconciled:false`, `actualBrokerChargesAndTaxesVerified:false`, `completeAccountWideExposureCertified:false`, `nativeProtectiveStopChildExchangeAckCertified:false`, `sourceEndpointsAtomic:false`, `netRealisedPnl:null`, `automaticClosureAuthorized:false`, `realisedPnlWriteAuthorized:false`, `liveNrmlBuyAuthorized:false`, `brokerWrites:0`, `localWrites:0`.
