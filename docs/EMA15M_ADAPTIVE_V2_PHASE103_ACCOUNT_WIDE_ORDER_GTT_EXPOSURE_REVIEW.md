# Phase103 — Same-option account-wide order, GTT and position exposure (read-only)

**Stacked DRAFT on Phase102 PR #107. No merge, deploy, exchange order, automatic settlement/P&L, new live NRML BUY release or forced 15:15 NRML positional exit.**

The required eventual product is real 1W/2W/4W/8W NRML option holding, not an intraday MIS surrogate. Phase90's explicit live NRML BUY block and MIS-only 15:15 square-off remain unchanged.

## Actual risk: a correct child BUY/SELL ledger is not the whole account

Phase101 stored unique original BUY trade IDs and Phase99 stored unique SELL child trade IDs. Phase102 compared them in one SQLite read and calculated **indicative** executed-premium difference. A separate external/manual BUY or SELL, open broker-native SL-M child, pending GTT rule, second native product or a stale portfolio snapshot can invalidate the inferred account exposure. A single fully-filled SELL child plus broker net=0 does not prove all account orders, GTT state, historical fills, capital, or charges were independently reconciled.

Critically, official [Upstox Get Order Book API](https://upstox.com/developer/api-documentation/get-order-book/) and [Get Order Status API](https://upstox.com/developer/api-documentation/get-order-details/) document that ordinary order rows are trading-day limited; older completed orders may be absent. Official [GTT Order Details](https://upstox.com/developer/api-documentation/get-gtt-order-details/) uses a separate subsystem and cannot retrieve completed GTT orders. Therefore **missing original BUY/SELL or GTT from current source is NOT evidence that it never existed**, and a visually clean account snapshot cannot prove historical absence.

## Implementation — precise sources, no account mutations

- Pure `auditAccountWideExposureReadOnly()` takes a validated exact authenticated account, native option instrument key, product MIS/NRML, original BUY ID, persisted SELL child ID, original whole-lot BUY quantity, cumulative uniquely observed SELL child fills and all three **full-account** broker GET datasets: short-term positions rows, ordinary order book, GTT list.
- Validates all full-source rows for structural quality, including unrelated contracts (missing/unknown rows defeat complete account-census claims). Requires exactly one row for the exact option and correct I/D product; duplicate rows, absent flat position rows, unreadable net quantity or conflicting cross-product position are **not** silently netted. Net must equal original long minus durable child SELL fills. Other instrument positions are counted as contextual exposures but **account-wide margin/capital is not certified**.
- Checks exact original BUY and exit SELL child IDs when currently visible. Duplicate account order IDs, wrong product/side/status, terminal SELL without complete fill, changed child execution quantity or missing order status are conflicts or SOURCE UNKNOWN. **A missing original BUY or exit SELL in current-day order book is source-history INCOMPLETE**, not an automatic rejection/execution inference; the Phase99–102 immutable journals remain separate.
- Examines other same-option BUY/SELL orders: any pending BUY may increase the net; any additional completed BUY/SELL with executions or active SELL/SL/SL-M may create outstanding duplicate exposure. A cancelled sibling SELL with zero *verified reported* fills can be noted as historical, while missing fill count is INCOMPLETE, not zero. Cross-product (MIS I vs NRML D) order and GTT rows block.
- GTT SELL STOPLOSS/TARGET children that remain SCHEDULED/ACTIVE/TRIGGERED may execute later and **always conflict** with claiming no additional exposure; TERMINAL completed/cancelled GTT history is **INCOMPLETE**, since independent child/trade evidence is not covered here. Parent-child order ID references are not equated with an exchange ACK or stop-fill guarantee. A pending GTT BUY is also a possible net-increase risk.
- `reviewAccountWideExposureBrokerReadOnly()` matches the **authenticated connected Upstox account BEFORE** issuing GETs and reads order-book, then GTT list, finally the broker's full short-term position rows using `getVerifiedNrmlPositionRows()` (despite its historical name this source returns all short-term position products, not only NRML). Any null/error remains incomplete. Reads are sequential to reduce, not eliminate, stale evidence. No place/cancel/modify/write method exists in this interface.
- New **SUPERADMIN-only** `POST /api/ema15m/account-wide-exposure-review`, body `{positionId,expectedAccountId}`. Finds one durable `EXIT_PENDING` exact position and its BUY/SELL IDs, reads the last Phase99 SELL child snapshot from a private Phase102 joint ledger, invokes the read-only broker census, then reads the ledger **again** to detect local mutations during network GET awaits. It also attaches only Phase102's **redacted joint receipt state**, not raw receipt rows or indicative P&L. This does not make remote data atomic or certify historical source coverage.
- Fixed reports have explicit `BROKER_SOURCES_INCOMPLETE`, `CURRENT_DAY_BROKER_HISTORY_INCOMPLETE`, `SAME_CONTRACT_ACCOUNT_EXPOSURE_CONFLICT`, `NO_VISIBLE_EXTRA_EXPOSURE_NOT_CERTIFIED`, invalid/account mismatch states. **Every** state hardcodes `brokerGetEndpointsAtomic:false`, `historicalOrdersCompletelyCovered:false`, `accountWideCapitalAndMarginReconciled:false`, `independentExchangeChildAckCertified:false`, `protectiveStopCoverageCertified:false`, `confirmedExitSettlementAuthorized:false`, `netRealisedPnlAuthorized:false`, `automaticPositionClosureAuthorized:false`, `liveNrmlBuyAuthorized:false`, `brokerWrites:0`, `localWrites:0`. Response holds only fixed sanitized reason codes, statuses and aggregate counts; **no account ID, token, native contract key, raw order/GTT/trade IDs or prices**.
- **31 new synthetic/negative-control tests** cover full/partial/flat net, overnight missing original BUY, absent exit child in day book, no flat portfolio row, stale/duplicated net, simultaneous other-product exposure, active/filled extra BUY, open native SL-M SELL, cancelled SELL partial fills vs zero fills, unknown sibling fills, duplicate order IDs, incomplete child status, scheduled dual GTT STOPLOSS/TARGET, GTT BUY, malformed unrelated account rows, authenticating before GETs, transport errors/redaction, strict read sequence and code-level absence of order/SQLite writes. Plus previous **423 expected** targeted Phase79–102 cases yields **454 expected** targeted synthetic checks; actual Github CI result is authoritative.
