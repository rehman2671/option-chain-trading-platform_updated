# Phase91 — Read-only broker-authoritative NRML position and stop/GTT candidate audit

**DRAFT, staged on Phase90 PR #95; no broker order write, release, merge, deploy, or live NRML trading activation.** Live NRML is an explicit platform requirement, but the operator's goal must be implemented with actual protective-stop lifecycle evidence. Existing Phase90 live NRML BUY interlocks remain hard-disabled regardless of source flags, local user settings or these read-only observations.

## New diagnostic path

- `UpstoxProvider.getVerifiedNrmlPositionRows()` uses the broker's live short-term positions API in **read-only mode**. It returns `null` on missing token, API failure, malformed payload or disconnect, never the UI helper `getPositions()`'s ambiguous empty-list fallback. This matters when the broker has a genuine exposure but the portfolio lookup fails.
- `reviewNrmlBrokerReadOnly()` uses only four explicitly whitelisted read methods: `getLiveConnectionStatus`, `getVerifiedNrmlPositionRows`, `getOrderBook` and `getGttOrders`. It compares the exact expected account ID against the authenticated broker connection **before** fetching any private account data; then collects portfolio, order-book, GTT responses concurrently. A transport failure or missing any endpoint returns `BROKER_EVIDENCE_INCOMPLETE`. The API endpoints are independent, **not an atomic market-wide snapshot**.
- Pure `auditNrmlBrokerEvidence()` verifies the exact account, instrument key, product code **D** for NRML, positive net long quantity (one unambiguous matching NRML position record, multiple of operator-declared lot), no parallel MIS contract exposure, matching expected quantity, and inspects all visible active SELL stop orders and GTT SELL legs for duplicates, unknown/cancel-pending/modify-pending states and quantity mismatch.
- Active SL/SL-M SELL orders and pending GTT SELL rules are counted **as provisional observations**, never as matched, acknowledged broker-native protective child exchange orders. A GTT order is a broker-side instruction that might not yet have a child order on the venue. Duplicate GTT plus exchange SELL may also represent order activation; **without lineage and final authoritative broker child ID, the state is unresolved, not safely covered**.
- No matter how good these independent broker lists look, every report sets `sourceEndpointsAtomic:false`, `protectiveChildExchangeAckVerified:false`, `realBrokerStopFillGuaranteed:false`, `liveNrmlBuyAuthorized:false`, and `ordersPlacedOrCancelled:0`. Report contains only bounded counts and fixed reason codes, not broker account ID, raw order ID, instrument key, quoted BID, token, or vendor source.
- Superadmin-only `POST /api/ema15m/nrml-broker-review` requires explicitly supplied **expected** broker account ID, instrument key, long quantity and lot size; those user-provided values are **comparison targets, not independently authenticated ownership, instrument master or exposure**. Endpoint calls only the whitelisted read-only method. Response omits account/order IDs and cannot enable trading. It is not a substitute for complete account-wide reconciliation, which remains outside this focused per-instrument diagnostic.

## Failure semantics and limitations

Unknown or mismatched account/position/product/quantity, missing API responses, malformed or duplicate orders, conflicting active BUYs, cancel pending and unknown SELL/GTT status fail closed. Real order-book statuses, rule schemas and provider version changes must be verified against actual Upstox API documentation and an authorised sandbox/controlled account. A broker order book may include previously completed or cancelled SELLs; completion of one SELL changes actual net exposure and must be reconciled against current broker positions before any new order.

**Real-world release blockers still open:** issue #20 requires independently linked exchange child acknowledgements including account/product/instrument, protected quantity and native stop lifecycle, cancel/replace and UNKNOWN/partial-fill/restart recovery. Issues #17–19 and #21–22 require licensed option BID/ASK/depth with original event/receipt timestamps, verified NSE/BSE calendar/expiry/lot changes, independent OOS and human security/legal/capital-risk approvals. GTT triggers do not guarantee fills across overnight gaps. This phase does not implement GTT placement nor grant live NRML BUY permission. NRML positions must **not** be forcibly exited at 15:15; existing MIS 15:15 process remains preserved.
