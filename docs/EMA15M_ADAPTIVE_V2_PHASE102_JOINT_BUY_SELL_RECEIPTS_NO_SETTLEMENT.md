# Phase102 — Joint original BUY and SELL trade-ID receipts (preview only)

**Stacked DRAFT on Phase101 PR #106. No merge/deploy, no brokerage orders, no automatic CLOSED, no realised/net P&L posting and no live NRML BUY release.**

The goal is eventual LIVE multi-day positional NRML index-option CE/PE for 1W/2W/4W/8W tenors, without the legacy intraday MIS 15:15 forced exit. Phase90 keeps real-money NRML BUY fail-closed until broker-native stop child ACK and independent risk approval. The MIS-only scheduled squareoff remains separate.

## Why Phase102 matters

Phase99 persisted broker-reported SELL child/trade-ID snapshots; Phase100 offered an intentionally unapproved settlement preview using a locally stored original BUY order fill summary. Phase101 added immutable **individual original BUY** execution IDs. Prior to Phase102, those BUY and SELL evidence ledgers had not been jointly checked under a single private SQLite read snapshot, so a user could misread the Phase100 gross price difference as proven original-buy cost.

Phase102 explicitly reconciles the two **broker-reported** trade-ID sets and their quantities/weighted prices, independently of whether an original broker order-placement ACK happened to say `FILLED`. It is **not** a broker/exchange-authoritative settled cash ledger.

## Design and actual code

- `adaptiveJointTradeReceiptReconciliation.ts`: pure `previewJointBuySellReceipts()` first requires Phase100 SELL child, immutable SELL trades, status/quantity progression and current broker net to be consistent. Missing original BUY receipt or missing original execution records returns **SOURCE_MISSING_OR_UNVERIFIED**, never fabricated zero-cost entry.
- Exact match across original durable position, original fully-filled entry attempt, account, native option contract, product MIS/NRML, entry broker order ID, immutable original BUY receipt header and full original quantity. Every original BUY trade must have a unique immutable trade ID, positive whole-number executed quantity, strictly positive paise-compatible execution price and exact original broker-reported exchange reference. Sum of individual BUY fills must equal original long quantity, and its quantity-weighted average must match durable entry and original receipt to within one paise. Invalid/missing/mutated IDs, prices or quantities fail closed.
- Every SELL trade ID must also be unique and distinct from BUY IDs. Total broker-reported SOLD quantity must match Phase100's latest child fills and must not exceed original BUY total; remaining broker portfolio net must exactly match original BUY minus SELL. Inconsistent original BUY, SELL, saved child state, source truncation or stale broker net never yields a positive indicative number.
- `indicativeGrossTradeDifference` uses guarded integer paise arithmetic: reported SELL proceeds **minus quantity-weighted average original BUY cost for sold units**, rounded to two decimal places. This is an **illustrative gross premium difference**; not FIFO tax lots, final realised profit, margin requirement, taxes, brokerage, STT, GST, exchange fees or audited settlement. Can be negative.
- `dbEngine.readEmaJointBuySellEvidence()` reads Phase99 SELL child observations and trade IDs together with Phase101 original BUY receipt and BUY trade IDs in one private SQLite transaction. It uses the existing Phase100 read as a nested SAVEPOINT on the same SQLite connection. No mutation or network calls inside DB transaction. A current Upstox native net-position GET is still separate and **not atomic** with either SQLite or the exchange.
- New SUPERADMIN-only `POST /api/ema15m/joint-receipt-reconciliation-preview` requires exact durable `EXIT_PENDING` position and authenticated connected broker account ID match. It fetches **only** current broker net via an existing read-only Upstox GET, then invokes the private SQLite reader and pure preview. Returns bounded aggregate counts and static generic reason codes plus optional indicative gross; never returns broker account, order IDs, original option instrument, individual trade IDs, raw BUY/SELL prices or access token.
- Every report still hardcodes `chargesAndTaxesIndependentlyVerified:false`, `originalBuyExchangeExecutionsIndependentlyCertified:false`, `sellExchangeExecutionsIndependentlyCertified:false`, `externalAccountOrdersAndGttsReconciled:false`, `sourceSnapshotsAtomic:false`, `netRealisedPnl:null`, `automaticPositionClosureAuthorized:false`, `realisedPnlWriteAuthorized:false`, `liveNrmlBuyAuthorized:false`, `manualRiskSignoffRequired:true`, `brokerWrites:0`, `localWrites:0`.
